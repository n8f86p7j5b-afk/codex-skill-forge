# 刻耳柏洛斯系统：缘起、用途与使用说明

## 这个 Skill 是怎么诞生的

刻耳柏洛斯系统起源于一个关于“人格蒸馏”的想法：

如果大模型可以被蒸馏，那么一个人长期积累下来的行为痕迹、价值偏好、决策风格，是否也可以被整理成某种可复用的“内在议事系统”？

最初的想法很简单：当一个人遇到重要问题时，不直接让 AI 给建议，而是让几个不同的“我”分别发言。例如：

- 工作中的我；
- 生活中的我；
- 最核心身份或底线中的我。

它们先独立表达立场，再互相质询，最后形成决议。

但讨论很快发现：如果只是让 AI 扮演几个角色，这会变成普通 Prompt 角色扮演，容易空泛，也容易迎合用户。真正有价值的，不是让 AI 编出三个角色，而是让 Agent 通过访谈、选择记录、真实行为和后续复盘，逐渐形成三个可校准的内在分身。

于是，刻耳柏洛斯系统从一个“三个角色给建议”的想法，逐步变成了一个可移植的 Agent Skill / 协议包。

## 它有什么用

刻耳柏洛斯系统用于处理那些不是简单利弊分析能解决的选择。

这类选择通常有几个特征：

- 不是信息不足，而是内部拉扯太强；
- 不是没有答案，而是每个答案都要牺牲一部分自己；
- 工作、生活、身份、责任、欲望、尊严之间互相冲突；
- 用户需要的不只是建议，而是看清自己内部到底谁在反对、谁在害怕、谁在保护什么。

它适合的问题包括：

- 要不要离职、转岗、创业、接受某个机会；
- 要不要继续一段关系、合作或长期承诺；
- 要不要为了稳定牺牲创作、自由、成长或身体；
- 要不要为了事业牺牲家庭、健康或内在尊严；
- 要不要开口、忍耐、撤退、谈判或重启。

它不适合替代专业意见。医疗、法律、重大财务、安全和心理危机类问题，只能作为反思辅助，不能当作专业建议。

## 三个分身是什么

刻耳柏洛斯系统默认使用三个内在分身：

### Alpha

Alpha 是工作中的我，或者说在世界中必须交付、竞争、承担责任、保持能力的那部分。

它关心：

- 专业判断；
- 资源和机会；
- 执行可行性；
- 职业信用；
- 长期位置；
- 能力是否被浪费。

### Beta

Beta 是生活中的我，或者说有身体、有情绪、有关系、有日常消耗的那部分。

它关心：

- 身体和睡眠；
- 情绪恢复；
- 亲密关系；
- 日常秩序；
- 自由感；
- 长期疲惫和隐形代价。

### Gamma

Gamma 是核心身份与底线中的我。

它不是预设的“父亲”“母亲”“男人”“女人”“伴侣”或任何固定身份。Gamma 必须由用户自己定义。

它可以保护：

- 家庭信任；
- 创作生命；
- 信仰；
- 诚实；
- 健康；
- 自由；
- 长期自尊；
- 公平感；
- 责任；
- 某种用户自己命名的核心身份。

Gamma 的关键问题是：

> 有什么东西，是我不应该为了成功、稳定、认可或短期轻松而随便交易掉的？

## 它和普通 AI 分析有什么不同

普通 AI 分析常常会给出：

- 利弊表；
- 行动建议；
- 风险提醒；
- 总结性结论。

刻耳柏洛斯系统要求更严格：

1. 三个分身必须先独立表态。
2. 不能一开始就混合成一个综合建议。
3. 必须有交叉质询。
4. 每个分身都要暴露自己的盲点。
5. 质询后必须修正或坚持立场。
6. 最后才由主席汇总。

如果没有可见的互相质询，它就不是一次有效的刻耳柏洛斯议事。

## 标准运行流程

一次完整的刻耳柏洛斯议事包含四轮。

### Round 1：独立立场

Alpha、Beta、Gamma 各自只基于自己的卡片和同一个议案发言。

每个分身要说明：

- 我在保护什么；
- 我害怕什么；
- 我想为用户争取什么；
- 我的投票；
- 我的理由；
- 我看到的收益和代价；
- 最坏结果；
- 我要求的边界。

### Round 2：交叉质询

三个分身互相挑战。

每个分身至少要：

- 向另一个分身提出一个尖锐问题；
- 回答别人对自己的挑战；
- 说出自己的一个盲点。

这一步不可跳过。哪怕三个分身一开始意见一致，也必须质询。

### Round 3：修正立场

每个分身根据质询结果重新表态：

- 我改变了什么；
- 我仍然坚持什么；
- 我的最低可接受条件是什么；
- 我的最终投票是什么。

### Round 4：主席汇总

主席不是第四个人格。主席只负责整理，不新增价值判断。

最终输出应包含：

- 行动项；
- 执行边界；
- 复盘节点；
- 停止条件；
- 少数派意见；
- 需要验证的现实信息。

## 怎么使用

### 如果你的 Agent 支持 Codex 风格 Skill

把 `cerberus-system/` 放进 Skill 目录，然后说：

```text
用刻耳柏洛斯系统处理这个决定。
```

或：

```text
Use $cerberus-system for this decision.
```

### 如果你的 Agent 不支持 Skill 目录

也可以把它当作一套普通 Agent 协议使用：

1. 让 Agent 读取 `cerberus-system/SKILL.md`。
2. 根据需要读取 `references/` 中的文件。
3. 如果用户表达困难，读取 `adaptive-interviewing.md`。
4. 如果要完整议事，读取 `council-protocol.md`。
5. 如果分身太机械，读取 `living-parts.md`。
6. 如果要长期复用，读取 `productization.md` 和 `templates.md`。

## 第一次使用应该怎么开始

第一次不应该让用户填长表格。

Agent 应该像访谈一样，一次只问一个问题：

```text
最近有什么工作选择，比较能代表你的做事方式？
```

如果用户说不清楚，Agent 应该切换成选择题，而不是要求用户“更深入地表达”。

例如：

```text
工作中遇到不合理的事情时，你更接近哪一种？
A. 忍着，先保护自己
B. 委婉提出
C. 直接挑战
D. 私下绕开
E. 开始计划离开
```

这样刻耳柏洛斯系统不依赖用户特别会表达，也能逐渐建立可用画像。

## 为什么需要持久化画像

刻耳柏洛斯系统不应该每次都重新配置。

第一次初始化后，Agent 应该保存或输出一个简洁的 Cerberus Profile，其中包含：

- Alpha / Beta / Gamma 的核心描述；
- 三个分身的决策模式；
- Gamma 的 non-negotiables；
- 已知盲点；
- 历史校准记录。

之后再次使用时，应优先读取已有画像，只补当前决策需要的信息。

## 我们讨论中的关键节点

这个 Skill 的形成经历了几个重要转折：

### 1. 从“Prompt 角色扮演”转向“真实行为蒸馏”

最初可以很容易写成三个角色 Prompt，但这被否定了。

原因是：用户需要的不是 AI 想象中的三个角色，而是基于真实行为、选择和价值排序形成的可校准分身。

### 2. 从复杂 RAG 转向轻量 Persona Cards

曾经考虑过邮件、聊天记录、项目文档、本地向量库等方式。但这会带来隐私、部署和可用性问题。

最终选择轻量方案：

- 结构化访谈；
- Persona Cards；
- 决策日志；
- 后续校准。

### 3. 从“三个视角总结”转向“必须交叉质询”

测试时发现，如果只是 Alpha、Beta、Gamma 分别给观点，再由 AI 总结，系统会退化成普通分析。

因此加入硬规则：

> 没有 Round 2 交叉质询，就不是有效的刻耳柏洛斯议事。

### 4. 从“冷冰冰的分析模块”转向“活体分身”

三者不应该只是工作、生活、价值三个栏目。

它们应该像人的一部分：

- 有保护欲；
- 有害怕；
- 有渴望；
- 有防御姿态；
- 有可能误伤其他部分；
- 也有可能互相拯救。

因此加入了 `living_signature` 和 `living-parts.md`。

### 5. 从“固定第三身份”转向“身份中立 Gamma”

Gamma 不能默认是父亲、母亲、男人、女人、伴侣或任何社会身份。

它必须由用户自己定义。

这让系统可以适配不同性别、关系结构、文化背景和人生阶段的用户。

### 6. 从“Codex Skill”转向“通用 Agent Skill / 协议包”

项目最初以 Codex Skill 形式实现，但它不应该只属于 Codex。

现在的定位是：

> 一个模型无关、Agent 可移植的 Skill / Protocol。

Codex 可以使用，其他支持长指令、工具调用或自定义工作流的 Agent 也可以使用。

### 7. 从“英文模板”转向“语言跟随”

中文用户不应该被迫使用英文提示词或英文标题。

因此系统要求：

- 中文输入，中文响应，默认称“刻耳柏洛斯系统”；
- 英文输入，英文响应，称“Cerberus System”；
- 混合输入，跟随主语言。

## 这个 Skill 的核心精神

刻耳柏洛斯系统不是为了让 AI 替用户决定。

它的意义是：

> 让一个人内部那些彼此冲突、彼此保护、彼此误解的部分，能够被平等地听见，并在可见的质询中形成一个有边界、有复盘、有异议记录的行动方案。

它不是答案机器。

它是一间内在议事厅。
